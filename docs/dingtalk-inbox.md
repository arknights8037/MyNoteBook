# 钉钉消息连接器与收件箱

> 状态（更新于 2026-07-29）：支持钉钉企业内部应用机器人通过 Stream 模式接收单聊和群内 @机器人消息，提供凭据保护、断线重连、来源分类、本地去重、统一时间线与本地处理状态。当前不发送或回复消息，也不读取完整群历史。

## 1. 页面归属

- “连接与扩展 → 连接器”负责验证凭据、启动、暂停和删除钉钉连接；
- “收件箱 → 消息”负责阅读已收到的钉钉消息；
- “收件箱 → 待处理 / 全部动态”将钉钉消息、邮件和 RSS 按来源时间合并；
- 每个连接可设置独立来源分类，并在消息页和统一收件箱中筛选。

## 2. 接入方式

1. 在钉钉开放平台创建企业内部应用；
2. 为应用添加机器人能力，将机器人消息接收模式配置为 Stream 模式；
3. 发布应用并安装到当前企业；
4. 从“凭证与基础信息”复制 Client ID（旧称 AppKey）和 Client Secret（旧称 AppSecret）；
5. 在 MyNoteBook 中验证并连接。

运行时通过 `POST https://api.dingtalk.com/v1.0/gateway/connections/open` 注册 `/v1.0/im/bot/messages/get` 回调 Topic，再使用返回的短期 ticket 建立 WebSocket。ticket 不落盘，也不会复用。

## 3. 接收边界

当前版本只接收机器人真正可见的消息：

- 用户与机器人的单聊消息，无需 @；
- 群聊中明确 @机器人的消息；
- 文本和富文本会保存为本地纯文本；图片、文件、语音、视频等暂以类型占位显示。

它不是用户钉钉账号的完整消息同步器，不会读取未 @机器人的群消息、历史会话、其他私聊或频道内容。界面必须持续展示这个边界，避免用户误以为连接器拥有完整企业消息权限。

## 4. 在线语义与时间

钉钉机器人消息是在线 Stream 回调，不是主动拉取：

- `last_connected_at` 表示最近一次成功建立 Stream 的时间；
- `last_event_at` 表示最近一次收到机器人消息的时间；
- 消息 `sent_at` 使用钉钉负载中的创建时间，`received_at` 使用 Stream 到达时间；
- 应用启动并打开数据库后会自动恢复所有已启用连接；
- 断线后按 2、4、8 秒逐步退避，最长 60 秒，并重新申请 ticket。

钉钉官方说明机器人消息采用 fire-and-forget 模式。应用关闭或网络中断期间的消息没有可靠补拉保证，因此界面不能显示“同步完成”或暗示无缺口历史。

## 5. 安全与数据最小化

- Client Secret 使用现有 OS 凭据保护的数据密钥加密保存，不进入 SQLite；
- SQLite 只保存 Client ID、展示名、分类、运行状态、会话和标准化消息字段；
- 不保存 Stream ticket、sessionWebhook 或完整原始回调 JSON；
- 认证与网络错误在写入状态和日志前经过敏感内容脱敏；
- 当前连接器完全只读，不自动回复、不主动发送，也不调用远端删除或已读接口。

## 6. 可靠性和去重

- 会话以“连接器 + 钉钉 conversationId”唯一；
- 消息以“连接器 + 钉钉 msgId”唯一；缺少 msgId 时使用 Stream envelope messageId；
- 收到回调后在同一数据库事务中更新会话、插入消息和推进 `last_event_at`；
- 重复回调使用唯一约束和 `INSERT OR IGNORE` 去重；
- 机器人回调按钉钉协议返回包含相同 messageId 的 ACK，系统 ping 原样回传 opaque。

后续若要实现更完整的企业消息采集，应作为独立权限模型设计，评估审计、留存、成员授权和远端查询 API，不能把机器人可见范围静默扩大成用户账号全量同步。
