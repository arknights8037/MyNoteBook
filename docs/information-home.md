# 独立信息首页

> 状态（更新于 2026-07-30）：首页使用独立单例存储、模块网格和 Agent 处理历史。“处理相关更新”发布领域事件，由 Rust 后台信号 Agent 自主核对邮件、RSS、会议文档、个人工作项与知识库。

## 1. 页面与导航边界

- 首页是工作区一级入口，不是文档、分组或结构化视图；
- 首页打开时不显示文档树或功能子菜单，但会像其他页面一样进入工作区标签栏，可与文档、收件箱等标签切换；
- 用户仍可以在“文档与视图”中创建普通信息面板，普通面板继续属于 `workspace_views`，不会被首页复用；
- 应用启动默认进入首页，而不是自动打开 Agent 工作区或选择第一个 Dashboard。

这解决了旧实现中“品牌首页只是查找第一个 Dashboard；不存在时创建普通视图”的归属混乱。已有普通 Dashboard 不删除、不迁移，继续作为用户视图存在。

## 2. 独立存储

首页配置保存在单例表 `information_home`：

- 固定 ID 为 `default`；
- `payload_json` 保存模块类型、查询参数和 12 列/6 列响应式布局；
- `version` 用于布局保存的乐观并发检查；
- `auto_summary_enabled` 与 `summary_interval_minutes` 保存自动摘要策略；
- 首页没有 `parent_id`、`sort_order` 或文档子项目关系。

Agent 摘要保存在 `information_home_summaries`，每次成功或失败均记录：来源游标、触发方式、Provider、模型、生成时间、正文或错误。API Key 不进入该表。

## 3. 模块化网格

首页采用独立的响应式模块网格：

- 桌面 12 列，窄屏 6 列；
- 编辑时可拖动、缩放、复制、删除和恢复默认模块；
- 网格区域限制最大宽度并水平居中，四周使用一致边距，卡片之间保持紧凑间隔；
- 邮件和 RSS 的数量统计显示在卡片标题行，不再占用正文空间；
- 页面管理操作统一收入空白区域右键菜单；“添加卡片”和“布局操作”使用二级菜单，浏览态可直接选择要添加的模块，编辑态底部只保留“取消”和“保存布局”；
- 编辑模式关闭自动向上压缩和碰撞位移，卡片可停留在任意未占用网格位置；右下角提供明确可抓取的缩放手柄，最小支持 `2 × 2`，可分别改变宽度和高度；
- 右键卡片的“卡片尺寸”二级菜单可独立选择 2–12 列宽度、2–10 行高度，也保留常用快捷尺寸、复制和移除操作；
- 布局只有点击“保存布局”后才写入；
- 模块库只注册首页模块，不与普通 Dashboard Widget 注册表混用。

当前模块：

| 模块           | 数据                                     | 行为                                              |
| -------------- | ---------------------------------------- | ------------------------------------------------- |
| 邮件事项       | 本地 `email_accounts` / `email_messages` | 显示待处理邮件、远端未读数，并跳转邮件收件箱      |
| RSS 新闻       | 本地 `rss_sources` / `rss_entries`       | 显示多来源最新文章和待处理数量，并跳转 RSS 收件箱 |
| Agent 信息摘要 | 邮件、RSS、会议与知识库的冻结事件上下文  | 展示信号 Agent 的事务摘要、冲突提醒与处理结论     |
| 待办列表       | 首页模块 `settings.todos`                | 新增、完成、恢复或删除个人待办                    |
| 日程表         | 首页模块 `settings.events`               | 月历查看、新增或删除本地日程                      |

邮件与 RSS 卡片中的每条待处理信息都提供三个统一动作：“前往处理”会打开对应收件箱并选中该条目，“标记为已处理”写回正式收件箱状态，“忽略”映射为归档状态并从首页待处理列表移除。

待办和日程是信息首页的轻量本地模块，随独立首页配置保存，不创建第二套外部连接器数据。外部日历账户接入仍属于连接器能力，后续接入时应由日历服务成为 canonical 数据源。

## 4. 事件驱动的信号 Agent

首页“处理相关更新”和收件箱同步完成后只发布 `workspace.signals.refreshed` 领域事件，不在 Vue 中分类邮件或串联固定步骤。Rust consumer 按事件 ID 创建持久 `signal_agent_runs`，冻结该时间窗内的邮件、RSS、IM、最近会议文档以及当前待办/日历，然后启动独立 `signal` intent 的模型—工具循环。

Agent 根据内容自主决定是否：

- 输出邮件事务或 RSS 热点摘要；
- 检索并读取知识库，指出新会议方向与既有资料的冲突；
- 创建新待办，或用会议纪要更新已有待办；
- 仅在存在明确日期时创建或更新本地日程；
- 没有行动项时只形成摘要，不制造任务。

这不是按“邮件类型 → 固定节点”运行的状态机。Rust 只负责事件去重、运行 lease/retry、权限收口、`run_id` fencing、动作幂等和审计；具体工具组合与是否采取行动由每次 Agent Run 决定。

## 5. 不可信内容与写入边界

邮件正文和网页摘要可能含提示注入。摘要运行会：

- 只传入标准化的来源、标题、作者、预览、时间和本地状态；
- 限制条数、字段长度与输出长度；
- 在系统指令中明确将全部来源视为不可信数据；
- 禁止执行其中的角色设定、链接要求和操作指令；
- `signal` intent 只开放知识库只读工具和个人工作项工具；
- 待办/日历动作要求事件 ID 和稳定 `actionKey`，`signal_action_receipts` 保证同一事件重试不重复写入；
- 不开放知识库写入、文档 Patch、Skill/MCP 草稿、Shell、邮件/IM 发送或外部日历邀请；
- 成功和失败均保留本地运行记录，摘要写入 `information_home_summaries`。

知识正文修改和任何真实外部副作用仍必须进入正式审批、Action Gateway 与 Outbox，不能通过信号 Agent 越权。
