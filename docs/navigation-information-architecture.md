# 工作区导航与信息架构

> 状态（实现于 2026-07-28）：第一阶段导航重构已落地。本文定义主导航、功能侧栏和连接器内容的归属，避免后续 RSS、IM、邮件接入时按技术模块堆叠菜单。

## 1. 分类原则

导航按用户任务分类，不按 repository、插件类型或协议分类：

1. 日常入口回答“我现在要处理什么”；
2. 内容入口回答“工作资料在哪里”；
3. 管理入口回答“能力如何连接、运行和审计”；
4. 同一连接器的配置、内容和摘要必须分开呈现。

## 2. 当前主导航

```text
工作区
├─ 首页（品牌入口同样打开首页）
├─ 收件箱
├─ 工作
│  ├─ Agent 任务
│  └─ 自动化
├─ 文档与视图
├─ 知识
└─ 连接与扩展
管理
├─ 活动与审计
└─ 设置
```

- 首页打开现有第一个 Dashboard；不存在时创建默认信息面板。品牌按钮保留同一快捷动作。
- 收件箱是外部信息的日常处理入口，不保存账户配置。
- Agent 任务与自动化共享“工作”一级入口，但保留各自页面状态和领域模型；待确认与运行记录成熟后继续在该分类内扩展。
- 文档与视图继续承载用户创建的 Dashboard；品牌入口只是稳定快捷入口，不建立第二份 Dashboard 数据。
- 连接与扩展属于常用能力入口，已上移到工作区分组，统一承载连接器、Skills、MCP Client、MCP Server 和内置插件。
- 活动与审计是只读治理入口，不与普通收件箱动态混排。

## 3. 连接器的三处投影

| 位置       | 职责                             | RSS 示例           | 邮件示例           |
| ---------- | -------------------------------- | ------------------ | ------------------ |
| 连接与扩展 | 安装、授权、范围、同步和健康状态 | Feed URL、抓取频率 | OAuth、文件夹范围  |
| 收件箱     | 阅读、筛选、标记、关联和后续处理 | 未读文章、增量摘要 | 邮件会话、待回复   |
| 信息面板   | 跨来源摘要和异常提示             | RSS Briefing       | 重要邮件、连接异常 |

插件或 MCP 可以作为连接器的实现方式，但用户不应先理解实现方式才能找到收到的内容。

## 4. 收件箱分区

当前预留以下稳定分区：

- `pending`：需要用户阅读、判断或跟进；
- `all`：统一时间线；
- `rss`：RSS 内容；
- `messages`：IM 与协作消息；
- `email`：邮件会话；
- `failures`：授权、同步、解析和来源异常。

邮箱连接器已提供标准 IMAP 只读同步；RSS 与消息仍只展示真实零状态和规划状态，不生成模拟内容。

## 5. 后续数据边界

- RSS、IM、邮件分别保留 canonical repository 和来源权限。
- 收件箱使用统一只读 `SignalItem` 投影，不复制完整业务记录。
- Dashboard Widget 查询聚合摘要，不成为收件箱或连接器配置的替代页面。
- 将信号转为 Research、Task、Decision 或文档时，继续使用正式 command、确认和审计流程。
- 外发、回复、删除远端内容等副作用不得由收件箱列表直接绕过授权。

## 6. 下一阶段

1. 定义 `SignalItem`、来源身份、去重哈希和处理状态；
2. 先接入只读 RSS，再验证收件箱筛选、项目关联和 Dashboard 摘要；
3. 接入 IM/邮件前补齐账户权限、敏感内容和外发确认模型；
4. 有真实运行数据后再增加连接器数量、未读徽标和全局通知。
