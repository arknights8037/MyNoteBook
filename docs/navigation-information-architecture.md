# 工作区导航与信息架构

> 状态（实现于 2026-07-28）：第一阶段导航重构已落地。本文定义主导航、功能侧栏和连接器内容的归属，避免后续 RSS、IM、邮件接入时按技术模块堆叠菜单。

## 1. 分类原则

导航按用户任务分类，不按 repository、插件类型或协议分类：

1. 日常入口回答“我现在要处理什么”；
2. 内容入口回答“工作资料在哪里”；
3. 管理入口回答“能力如何连接、运行和审计”；
4. 同一连接器的配置、内容和摘要必须分开呈现。

## 2. 当前主导航

```text
工作区
├─ 首页（品牌入口同样打开首页）
├─ 收件箱
├─ 工作
│  ├─ Agent 任务
│  └─ 自动化
├─ 文档与视图
├─ 知识
└─ 连接与扩展
管理
├─ 活动与审计
└─ 设置
```

- 首页是独立单例信息面板，使用自己的布局和摘要存储，不进入文档树、视图树或子项目层级。品牌按钮打开同一独立首页。
- 收件箱是外部信息的日常处理入口，不保存账户配置。
- Agent 任务与自动化共享“工作”一级入口，但保留各自页面状态和领域模型；待确认与运行记录成熟后继续在该分类内扩展。
- 文档与视图继续承载用户创建的普通 Dashboard；普通 Dashboard 与首页相互独立，不共享布局版本或父子关系。
- 连接与扩展属于常用能力入口，已上移到工作区分组，统一承载连接器、Skills、MCP Client、MCP Server 和内置插件。
- 活动与审计是只读治理入口，不与普通收件箱动态混排。

## 3. 连接器的三处投影

| 位置       | 职责                             | RSS 示例           | 邮件示例           | 钉钉示例                  |
| ---------- | -------------------------------- | ------------------ | ------------------ | ------------------------- |
| 连接与扩展 | 安装、授权、范围、同步和健康状态 | Feed URL、抓取频率 | OAuth、文件夹范围  | 应用凭据、Stream 运行状态 |
| 收件箱     | 阅读、筛选、标记、关联和后续处理 | 未读文章、增量摘要 | 邮件会话、待回复   | 单聊与群内 @机器人消息    |
| 信息面板   | 跨来源摘要和异常提示             | RSS Briefing       | 重要邮件、连接异常 | 在线状态、消息异常        |

插件或 MCP 可以作为连接器的实现方式，但用户不应先理解实现方式才能找到收到的内容。

## 4. 收件箱分区

当前预留以下稳定分区：

- `pending`：需要用户阅读、判断或跟进；
- `all`：统一时间线；
- `rss`：RSS 内容；
- `messages`：IM 与协作消息；
- `email`：邮件会话；
- `failures`：授权、同步、解析和来源异常。

邮箱连接器已提供标准 IMAP 只读同步；RSS 已提供公共 Feed 条件同步、去重和纯文本阅读；钉钉已提供企业内部机器人 Stream 只读接收。三类内容进入统一时间线，钉钉仍明确限定为单聊和群内 @机器人消息，不宣称完整群历史同步。

## 5. 后续数据边界

- RSS、IM、邮件分别保留 canonical repository 和来源权限。
- 收件箱使用统一只读 `SignalItem` 投影，不复制完整业务记录。
- Dashboard Widget 查询聚合摘要，不成为收件箱或连接器配置的替代页面。
- 将信号转为 Research、Task、Decision 或文档时，继续使用正式 command、确认和审计流程。
- 外发、回复、删除远端内容等副作用不得由收件箱列表直接绕过授权。
