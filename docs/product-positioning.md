# 产品定位与愿景

本文定义 MyNoteBook 的对外产品类别、核心叙事、品牌主张和长期产品原则。它回答“为什么存在”和“希望创造什么价值”；已经实现的能力和技术边界仍以 [当前架构](architecture.md) 为准，尚未完成的工程事项以 [后续开发路线图](roadmap.md) 为准。

## 1. 核心定位

MyNoteBook 不应被定义为“带 AI 的知识库”，也不应宣传为“帮用户自动完成一切的 Agent”。

更准确的定位是：

> 面向知识工作者的桌面工作中枢：持续接收信息、组织上下文、协调任务，并将工作过程沉淀为可复用成果。

推荐的中文产品类别是：

> **AI 桌面工作中枢**

可选描述包括“知识与任务控制台”“个人工作操作系统”和“AI 原生知识工作台”。其中“操作系统”有想象空间，但容易超出当前能力；“知识库”又过于局限。“桌面工作中枢”更符合现有产品，也为后续扩展保留空间。

英文类别可根据语境使用：

- AI Workspace Hub
- Desktop Command Center for Knowledge Work
- Knowledge Work Operating System

标准产品描述：

> 一款本地优先的 AI 桌面工作中枢，帮助你收集信息、理解上下文、委派任务、沉淀成果，并将同一套知识转换为不同的表达形式。

## 2. 要解决的长期断裂

产品解决的不是某一个孤立功能问题，而是知识工作长期存在的结构性断裂：

1. 信息散落在网页、聊天、文档、会议和不同软件中。
2. 任务和资料彼此分离，执行时需要反复寻找上下文。
3. AI 能够生成内容，却不了解项目状态、历史决策和当前约束。
4. 工作完成后，过程没有沉淀，下一次仍然从头开始。
5. 同一份内容需要反复改造成汇报、文档、表格和幻灯片。
6. 传统自动化过度追求“无人操作”，难以处理复杂、模糊和高风险任务。

核心主张：

> 不是替你工作，而是让你的工作始终处于被理解、被组织、可继续的状态。

## 3. 产品不是什么

### 3.1 不是另一个聊天机器人

聊天结束后，重要信息不应留在孤立对话框里，而应进入项目、文档、任务、知识对象和历史记录。

### 3.2 不是另一个自动化平台

产品不承诺将复杂工作全部交给 AI。人负责目标、判断和责任；Agent 负责搜集、整理、执行和跟进。

### 3.3 不是另一个文档编辑器

文档不是唯一或最终容器，而是工作信息的一种视图。同一套内容还可以呈现为任务、时间线、表格、图表、看板或幻灯片。

### 3.4 不是静态知识库

知识不是被收藏后永久静止的条目。它会随着任务执行、外部信息和用户决策持续更新，并保留来源、版本、权威等级和审批状态。

## 4. 核心叙事：持续工作循环

整个产品可以浓缩为六个阶段：

```text
收集 Collect
  -> 理解 Understand
  -> 组织 Organize
  -> 委派 Delegate
  -> 表达 Present
  -> 沉淀 Retain
  -> 下一轮工作
```

### 4.1 收集 Collect

从网页、文件、聊天记录、邮件、会议、剪贴板和外部应用中接收信息。

对外表达：

> 不再手动搬运信息，让工作资料主动进入你的工作空间。

产品要求：输入必须保留来源、时间、所属空间和后续处理状态。尚未接入的来源应明确写作产品方向，而不是当前能力。

### 4.2 理解 Understand

识别信息属于哪个项目、涉及哪些人物、形成了什么事实或决策，以及可能对应哪些任务。

对外表达：

> 不只是保存内容，而是理解它和当前工作的关系。

产品要求：理解结果必须可解释、可确认，不能用不可追溯的模型输出替代正式知识。

### 4.3 组织 Organize

将输入转化为项目资料、事实、任务、事件、决策和知识条目。

对外表达：

> 让混乱的输入变成可以继续执行的上下文。

产品要求：Document、Knowledge、Work 和 View 各自承担明确职责，不能产生多个互相冲突的事实来源。

### 4.4 委派 Delegate

把适合执行的工作交给内置 Agent、外部 Agent、MCP 工具或人工协作者。

对外表达：

> 你决定方向，系统负责把任务交给正确的人或 Agent。

产品要求：委派必须携带冻结上下文、明确权限、验收条件和结果回收路径。

### 4.5 表达 Present

根据对象，将同一套核心内容生成文档、表格、图表、看板或幻灯片。

对外表达：

> 同一份工作，不必为不同对象重复整理。

产品要求：View 是可重建的表达，不是第二事实源；生成内容应记录依赖、版本和人工覆盖状态。

### 4.6 沉淀 Retain

把执行结果、重要决策、失败经验和最终成果重新写回知识体系。

对外表达：

> 每完成一次工作，系统就更理解你的项目。

产品要求：Agent Result 需要经过验证，ChangeSet 需要确认，正式写入必须进入受控的 Document/Knowledge 边界。

## 5. 差异化宣传支柱

### 5.1 自动保持工作连续性

传统 AI 产品强调“一句话完成任务”。MyNoteBook 更应强调：

> 即使任务无法一句话完成，工作也不会再失去上下文。

可用表达：

- AI 不一定替你完成工作，但它不应该让你每次重新解释工作。
- 任务可以暂停，但上下文不会丢失。
- 今天没有做完的工作，明天可以从正确的位置继续。
- 一个项目越做越轻，而不是越做越乱。

### 5.2 让信息进入工作流

用户通常不缺信息，缺少的是信息进入行动的路径。

> 收藏，是把信息留给未来。工作中枢，是让信息知道自己接下来应该去哪里。

对应能力包括识别所属项目、提取事实/任务/风险/决策、建议后续动作、关联已有资料，以及形成待确认的知识更新。

### 5.3 一源多视图与内容编译

核心概念：

> 内容只有一份，表达可以有很多种。

一份项目内容可以成为：

- 给自己看的项目工作台。
- 给团队看的任务看板。
- 给客户看的方案文档。
- 给管理者看的数据图表。
- 给投资人看的演示文稿。
- 给 Agent 使用的结构化上下文。

推荐将这项能力称为“一源多视图”或“内容编译”：

> 将项目知识编译为文档、表格、图表和演示文稿。

它强调的是单一事实源和多种表达，而不是简单罗列支持的文件格式。

### 5.4 Agent 结果形成长期资产

大多数 Agent 流程止于一段临时结果。MyNoteBook 的目标是让每次执行成为未来可调用的知识：

- 研究结果进入项目资料。
- 决策进入决策记录。
- 执行状态进入任务系统。
- 文件修改进入版本和审计历史。
- 经验和偏好形成可复用 Skill。
- 外部 Agent 的结果经过验证与确认后写回知识体系。

### 5.5 人的判断是控制核心

“人仍然参与”不是能力不足，而是产品原则。

推荐表达：

> AI 负责处理规模，人负责决定方向。

或：

> 自动化执行，不自动化责任。

对应的可信机制包括高风险确认、知识来源与版本、提案式修改、执行过程展示、外部写入握手、审计和撤销。

### 5.6 桌面是控制台

本地优先桌面应用不是另一个入口，而是工作状态的控制台。

> 浏览器标签页是工作发生的地方，桌面中枢是工作被组织的地方。

长期强调本地知识与文件、桌面级剪贴板/窗口/通知接入、后台运行、数据控制，以及与外部模型、Agent 和 SaaS 的受控连接。

## 6. 品牌文案结构

### 6.1 第一层：一句话品牌主张

首选：

> 让所有工作，都能从上一次结束的地方继续。

候选：

- 把散落的信息，变成持续推进的工作。
- 你的工作不缺 AI，缺的是一个中枢。
- 收集信息，组织工作，沉淀成果。
- 让知识参与工作，而不是停在文档里。
- 为复杂工作保留上下文。

### 6.2 第二层：标准产品说明

> MyNoteBook 是一款本地优先的 AI 桌面工作中枢，帮助知识工作者收集信息、理解上下文、协调人与 Agent、沉淀执行成果，并将同一套知识编译为不同的表达形式。

### 6.3 第三层：可信原则

- 本地优先，用户控制数据。
- 人决定目标和正式写入。
- Agent 运行携带明确上下文和权限。
- 关键结果有来源、版本、验证和审计。
- 内容只有一个事实源，视图可以按需重建。

## 7. 产品决策检查表

新增功能、页面或宣传内容应检查：

1. 它服务于六阶段循环中的哪一环？
2. 它是否减少了上下文丢失或重复整理？
3. 它产生的是正式事实、执行结果，还是可重建视图？
4. Agent 在其中负责规模处理，人的判断点在哪里？
5. 结果如何沉淀，并在下一次工作中被重新使用？
6. 是否清楚区分当前能力与长期愿景？

无法回答这些问题的功能，通常只是增加了一个孤立入口，而没有增强桌面工作中枢。
